# Mesas e Entrada — Next.js + Convex

Tables with 10 numbered chairs (1–10), one person per chair (convidado or acompanhante), door check-in, name search that tells you the table, table selector buttons, transfers between tables (guest + companion move together), Excel/CSV paste import and a QR card per person.

The data lives in **Convex**, so every phone at the door sees changes live.

---

## 1. Stack

| Part | What |
|---|---|
| Frontend | Next.js 16 (App Router), React 19, TypeScript |
| Database / backend | Convex (queries + mutations, realtime) |
| QR | `qrcode-generator` (drawn on a canvas into a PNG card) |
| Fonts | Young Serif, Figtree, JetBrains Mono via `next/font/google` (`lib/fonts.ts`) |
| Tests | `convex-test` + Vitest (in-memory, no deployment needed) |

## 3. Setup (first time)

Requirements: Node.js 20+ and a free Convex account (https://convex.dev).

```bash
npm install
npx convex dev          # log in, pick the project → writes .env.local and pushes the schema/functions
```

Leave `npx convex dev` running, or use the combined script:

```bash
npm run dev             # runs `next dev` and `convex dev` together
```

Open http://localhost:3000. The app starts empty: create a table with **+ Nova mesa** or paste a list with **Importar**.

### Environment variables (`.env.local`)

| Variable | Set by | Purpose |
|---|---|---|
| `CONVEX_DEPLOYMENT` | `npx convex dev` | which Convex deployment the CLI pushes to |
| `NEXT_PUBLIC_CONVEX_URL` | `npx convex dev` | URL the browser connects to |
| `NEXT_PUBLIC_APP_URL` | you | public address put inside the QR codes, e.g. `https://mesas.xalima.co.mz`. If empty, the address the app is opened from is used. **Set it before sending QR codes.** |

## 4. Deploy to production (Vercel)

1. Push the folder to GitHub and import it into Vercel.
2. In the Convex dashboard → *Settings → Deploy keys*, create a **Production deploy key**.
3. In Vercel → *Settings → Environment Variables* add:
   - `CONVEX_DEPLOY_KEY` = the key from step 2
   - `NEXT_PUBLIC_APP_URL` = your final domain
4. In Vercel, set the **Build Command** to:
   ```
   npx convex deploy --cmd 'npm run build'
   ```
   This pushes the Convex functions to production and sets `NEXT_PUBLIC_CONVEX_URL` for the build automatically.

## 5. Data model

**`mesas`** (index `by_numero`)

| field | type | notes |
|---|---|---|
| numero | number | table number, unique |
| nome | string | table name |
| cadeiras | number? | number of seats, 1–30 (missing = 10). Set in the table dialog ("Lugares") |

**`lugares`**: one document per occupied chair, i.e. one person (indexes `by_mesa_cadeira`, `by_codigo`)

| field | type | notes |
|---|---|---|
| mesa | number | table number |
| cadeira | number | 1–10 |
| nome | string | person's name |
| tipo | `"convidado"` \| `"acompanhante"` | |
| de | number \| null | for an acompanhante: chair of the guest they accompany |
| codigo | string? | 6-character QR code (A–Z without I/O, 2–9). Unique and never changes, even on transfer |
| entrada | boolean | check-in done |
| entradaHora | number \| null | check-in time (ms) |

Empty chairs are simply chairs with no document. Each table has its own number of seats (`cadeiras`, default `SEATS = 10`, maximum `MAX_SEATS = 30`, in `convex/lib.ts` and `lib/util.ts`). A table can only be reduced when the chairs being removed are free.

## 6. Server functions (all rules enforced on the server, atomically)

| Function | Does |
|---|---|
| `mesas.list` | all tables, ordered by number |
| `mesas.create {numero, nome, cadeiras?}` | errors "A mesa N já existe." / "Dê um nome à mesa." |
| `mesas.rename {numero, nome, cadeiras?}` | rename and/or change the number of seats; refused while a removed chair is occupied |
| `mesas.remove {numero}` | deletes the table **and its people** |
| `lugares.list` | all occupied chairs (live) |
| `lugares.byCodigo {codigo}` | find a person by QR code (case-insensitive) |
| `lugares.add {mesa, cadeira, nome, entrada, acompanhante?}` | new guest; the companion goes to the next free chair. Returns `{cadeira, acompCadeira}` |
| `lugares.update {mesa, cadeira, novaCadeira, nome, entrada, acompanhante?}` | edit; moving chair updates the companion's `de`; a guest without a companion can get one |
| `lugares.free {mesa, cadeira}` | "Libertar cadeira" |
| `lugares.toggleEntrada {mesa, cadeira}` | check-in on/off, stores the time (optimistic in the UI) |
| `lugares.transfer {mesa, cadeira, destMesa, destCadeira, destCadeiraAcomp?}` | guest + companion move together; code and check-in are kept |
| `lugares.ensureCodigo {mesa, cadeira}` | gives a code to records that have none |
| `lugares.importar {mesas[], lugares[]}` | paste import (the client sends batches of 200). Keeps the code and check-in of people already in those chairs |

Errors are thrown as `ConvexError("Portuguese message")` and shown in the dialog ("Essa cadeira acabou de ser ocupada. Escolha outra.", "Não há cadeira livre nesta mesa para o acompanhante.", …). Because the checks run inside one mutation, two door phones can never seat two people in the same chair.

## 7. Behaviour checklist

- **Header:** tables · seats, convidados + acompanhantes (1 per chair), people inside x/y with a progress bar.
- **Search:** results show the table number large, plus table name, chair, guest/companion relation, check-in time and the buttons **Check-in → Transferir → QR → Ver mesa**. Accents are ignored. Searching a QR code also finds the person.
- **Filters:** Todos / Por entrar / Entraram. **Views:** Mesas (always the opening view) / Lista.
- **Table chips:** Todas · Mesa 1 · Mesa 2 … with `entraram/ocupados`.
- **Button order on each person:** check-in, transfer (⇄), QR.
- **Register:** pick a free chair, enter the guest's name and optionally "Traz acompanhante?" (shows which chair they'll get). After saving a new guest the QR card opens, with a button to go to the companion's QR.
- **Transfer:** destination tables without enough free chairs are disabled; the two chairs are chosen for you and can be changed.
- **QR card:** 640×900 PNG with "A SUA MESA", table number, table name + chair, QR, name, role and code. The QR contains `NEXT_PUBLIC_APP_URL/#c-CODE`. Scanning it at the door opens the app on that person, ready for check-in.
- **Import format:** `N.º mesa; Nome da mesa; N.º cadeira; Nome; Tipo (C ou A); Acompanha cadeira`, separated by `;` or tab (paste straight from Excel). A header row is skipped.

### Access control (do this before the event)

The project ships without login: **anyone with the URL can open and edit.** Before giving the URL to door staff, put it behind authentication:

- **Quickest:** Vercel *Password Protection* on the whole site (paid Vercel plans).
- **Proper:** Convex Auth or Clerk. Then in each mutation check `const id = await ctx.auth.getUserIdentity(); if (!id) throw new ConvexError("Sem sessão.");`.
